Tooltip

A short hint that appears next to an element (above by default) on hover and on keyboard focus. The text comes from the data-tooltip attribute and CSS draws it; no JavaScript. Keep it short and never put essential information only in a tooltip (touch screens have no hover). For richer content, use a hover card or a popover. All components.

Plain HTML and CSS. The markup is also available as the snippet packages/ui/snippets/tooltip.html.

Icon buttons

The most common use: explain an icon-only button. The button keeps its own aria-label for screen readers.

Multiline

Add .oc-tooltip--multiline and every line break in data-tooltip (&#10; in HTML, \n in JavaScript) starts a new line.

With a title

For a title above the lines, put a .oc-tooltip__content inside the tooltip instead of data-tooltip, with a .oc-tooltip__title: a little larger, bold and always starting with a capital (::first-letter). A pseudo-element cannot style its own first line, so this needs a real element. The OmniaCSS color palettes use it for the color models of every swatch.

Placement

The default side is top. .oc-tooltip--bottom, --left and --right pick another preferred side.

Automatic placement

With CSS anchor positioning the tooltip is anchored to its element (position-area) and moves to the side that has room (position-try-fallbacks: flip-block, flip-inline): at the top of the window it shows below, at the right edge on the left. It is position: fixed, so a scrolling table or sidebar does not cut it off. The frame below has .contain-layout, which makes it the area the tooltip has to fit in: hover the buttons in its corners. Browsers without anchor positioning show it on the preferred side.

Inside a scroll container other than the page itself (an app shell whose main area scrolls, like these docs), Chrome 156 picks the side as if that area were not scrolled. Put .contain-layout on the area that scrolls (or on a frame inside it): the tooltip then keeps its preferred side there and flips at that frame's edges.

Reference

Styles live in packages/ui/src/components.css. Colors are theme tokens, so everything follows light and dark mode.

Class / attributeDescription
.oc-tooltipWrapper around the element that gets the hint.
data-tooltip="…"The hint text, drawn next to the element on :hover and :focus-within.
.oc-tooltip--bottom / --left / --rightPreferred side instead of top. With anchor positioning the tooltip flips to the opposite side (then the other axis) when there is no room.
.oc-tooltip--multilineKeeps the line breaks of data-tooltip: one line each, up to 20rem wide, left-aligned.
.oc-tooltip__contentChild element instead of data-tooltip (give it role="tooltip"): same bubble and placement, line breaks kept.
.oc-tooltip__titleTitle line inside .oc-tooltip__content: 0.875rem, bold, first letter always a capital.
--oc-tooltip-gapSpace between the element and the tooltip (default 8px).

Framework wrappers

The same markup and classes as React, Vue and Blade components.

<!-- React --> <Tooltip content="Saved to your library"><Button variant="outline">Hover me</Button></Tooltip> <!-- Vue --> <OcTooltip text="Saved to your library"><OcButton variant="outline">Hover me</OcButton></OcTooltip> <!-- Laravel Blade --> <x-oc::tooltip text="Saved to your library"><x-oc::button variant="outline">Hover me</x-oc::button></x-oc::tooltip> <!-- Multiline: the multiline prop (React, Vue) or :multiline="true" (Blade) --> <Tooltip content={"Autosave is on\nCtrl S saves now"} multiline><Button variant="outline">Save status</Button></Tooltip> <!-- With a title: heading (React, Vue, Blade) renders .oc-tooltip__content and .oc-tooltip__title --> <Tooltip heading="red" content={"HEX: #FF0000\nRGB: 255 0 0"}><Button variant="outline">Red</Button></Tooltip> <!-- Preferred side: side="bottom" | "left" | "right" (React, Vue, Blade) --> <OcTooltip text="Settings" side="right"><OcButton variant="ghost">⚙</OcButton></OcTooltip>
