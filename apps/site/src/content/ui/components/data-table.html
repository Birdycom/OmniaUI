Data table

A list table for business apps. Optional type tabs with counts, one toolbar (title, settings menu, search, trash pills, table or cards), filter selects, the table in a rounded frame with rich name cells and soft row actions, and a footer with the count, rows per page and page numbers. Search, filters, sort, pages and bulk actions run in the browser; column width and row drag come with OmniaUI Pro. All components.

Save the new row order v0.17.1

After a drop the table fires oc-datatable-reorder with { keys }: the row keys in the new order. The wrappers pass it on: onReorder(keys, { key, server }) in React and @reorder in Vue. In server mode (server) the script does not move the row itself; the event then also carries key (the dragged row) and server: true, so you save the order and render the rows again. Blade and Livewire listen with Alpine on the window (the event bubbles). The drag itself needs OmniaUI Pro (data-table-pro.js) and draggable.

<!-- React --> <DataTable title="Quote lines" draggable columns={columns} rows={rows} onReorder={(keys, { server }) => { saveOrder(keys); if (server) reload(); }} /> <!-- Vue --> <OcDataTable title="Quote lines" draggable :columns="columns" :rows="rows" @reorder="(keys) => saveOrder(keys)" /> <!-- Laravel Blade / Livewire (Alpine) --> <div x-data @oc-datatable-reorder.window="$wire.saveOrder($event.detail.keys)"> <x-oc::data-table title="Quote lines" draggable :columns="$columns" :rows="$rows" /> </div>

Your language, and only what a list needs v0.17.0

The demo below is in Dutch on purpose: it shows a list of games with every label translated through the labels prop. Every text of the table can be translated with labels (React, Vue, Blade): give any subset, the rest stays English. The texts the script writes itself (the pager, "3 selected", the sort line and the summary) go to data-oc-labels on the root as JSON; the components do that for you. A plain list does not need everything: filters={false} drops the trash pills and the selection actions (bulk on its own too), view={false} drops the table / cards switch (data-oc-no-grid), and pagination={false} shows every row on one page (data-page-size="0"). On paper only the table is printed: no toolbar, pager, checkboxes or actions, and no row breaks over two pages. Sort a column: the line under the toolbar is in Dutch too.

Server-driven v0.17.0

For a large list the server does the work: server (data-oc-server="true") means the rows are the current page and the table does not filter, sort or slice them. Every control asks for a new page instead: sort, search (after searchDelay, 300 ms), the trash pills, the column filters, the pager and rows per page fire oc-datatable-query with the whole query, and React and Vue turn that into callbacks (onSortChange, onPageChange …, or onQueryChange for one fetch). total drives the pager and the count, loading shows skeleton rows, the selection is kept over pages (selectedKeys), and visibleColumns adds a free column chooser. Drop late answers: only the newest request may fill the table. Try it: the demo has a fake API with a short delay.

Reference

Put .oc-data-table around the toolbar, the table and the footer. Load data-table.js once. The script wires every table on the page. Plain HTML or Blade: npx omniaui copy-js data-table puts it in public/js/oc-data-table.js, which starts on its own from <script type="module">.

React, Vue and Laravel

The wrappers render this markup and start the same script. All three take tabs (with a tone per tab), columnFilters, summary, archive, importable, selectable, draggable a truncate width and a hideBelow breakpoint (sm, md, lg) per column. Rich cells: React passes nodes (with <DataTableName>), Vue fills the cell-<key> slot (with <OcDataTableName>), Blade takes an HtmlString (or <x-oc::data-table-name>). Give a rich cell a plain values[key] for sorting, filtering and search. onBulk in React receives the action and the selected keys. Livewire: Omniacss\Livewire\DataTable renders the actions of actions() as soft icon buttons when they have an icon (and a tone).
