Command

Styling for a search field plus grouped, selectable results. Put it in a dialog.oc-modal for a palette. Filtering and aria-selected are driven by the wrapper component (set hidden on non-matching items). All components.

Items as children v0.18.0

Next to the groups / items data, the rows can be written as children: <CommandGroup> with <CommandItem> in React, <OcCommandGroup> / <OcCommandItem> in Vue. A row shows its own content (text, <strong>, an icon), is searched by its text (or label, keywords) and may have its own onSelect / @select. Filtering and the arrow keys and Enter work as before. The rows are read from the children as you write them (also inside fragments, .map() and v-for); a row inside your own wrapper component is not found, see Items in your own component. Blade: <x-oc::command.group> and <x-oc::command.item> (markup only). A row is a flex line with a gap after a leading icon: React and Vue put the text after the icon in one <span> for you; in HTML and Blade wrap mixed text such as <strong>New</strong> invoice in a <span> yourself.

Items in your own component v0.18.0

React Command and Vue OcCommand read their rows statically from the children as you write them: the direct children of the Command and of each group, also inside fragments (<>…</>, <template>), arrays from .map(), v-for and conditions ({open && …}, v-if). They look at the element type only and do not render your own components to see what comes out. So a CommandItem (or CommandGroup) inside your own wrapper component, such as <CustomerItem> that returns a <CommandItem>, is not found: the row is missing, cannot be searched and cannot be chosen, without an error. Keep CommandItem / OcCommandItem directly in the Command or group (in a .map() or v-for) and pass the data as props, call a helper as a function ({customers.map(customerItem)}, not <CustomerItem />), or hand the rows over as data: React groups, Vue items with group. Blade is not affected: <x-oc::command.item> is plain markup, so your own Blade component around it works.
