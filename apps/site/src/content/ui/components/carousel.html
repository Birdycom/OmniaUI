Carousel

A swipeable, snapping row of slides built from CSS scroll-snap. Where the browser supports ::scroll-button() and ::scroll-marker (Chromium 135+), the arrows and dot indicators are drawn by CSS itself; elsewhere anchor-link dots take over. No JavaScript. All components.

Loop

Add .oc-carousel--loop and two buttons, .oc-carousel-prev and .oc-carousel-next: after the last slide, next goes back to the first, and previous on the first goes to the last. The browser's own arrows stop at the ends and a click on a pseudo-element cannot be redirected, so this variant needs the small script @birdycom/omniaui/carousel.js (initCarousels()). Swipe, snapping, the dots and the keyboard stay CSS. Without the script the buttons stay hidden and the CSS arrows remain, so the carousel never breaks.

Platform features used

CSS featureRole
scroll-snap-typeMandatory snapping on the inline axis
scroll-snap-alignSlides center when snapped
scroll-marker-groupGenerates the dot indicators
anchor-nameArrow buttons anchor to the viewport
scroll-behaviorSmooth movement for buttons and dots

Anatomy

  • Viewport display: flex; overflow-x: auto; scroll-snap-type: x mandatory. Drag, swipe, wheel and keyboard scrolling all work natively.
  • Slides flex: 0 0 100% with scroll-snap-align: center; --halves/--thirds show several at once.
  • Arrows ::scroll-button(inline-start|inline-end), positioned with anchor positioning, disabled automatically at the ends.
  • Dots scroll-marker-group: after and ::scroll-marker; the current dot uses :target-current.
  • Fallback .oc-carousel-dots links jump to a slide id; hidden when markers are supported.

Accessibility and keyboard

Accessibility

  • Give the viewport tabindex="0", role="region" and a label so keyboard users can scroll it with the arrow keys.
  • Slides are role="group" with aria-roledescription="slide" and "n of m" labels.
  • The arrows set content: "→" / "Next slide", so their accessible name is separate from the glyph. Auto-play is deliberately not included.
  • Smooth scrolling is only enabled under prefers-reduced-motion: no-preference.

Keyboard

  • Tab focuses the viewport; ←/→ scroll to the previous or next slide (snap points).
  • Arrow buttons and dots (where supported) are focusable and activate with Enter/Space.
