Webicon

An icon by its name, such as mdi:home-outline or flag:be-4x3, from the six webicon sets: MDI, MDI Light, Material Symbols, SVG Spinners, Flags and VSCode Icons. It is drawn as inline SVG in currentColor, from icon data your app bundles itself: nothing is fetched from the network and no icon script runs in the browser. See every icon in the webicons catalog. All components.

Five fixed sizes for places that need the same icon size everywhere, and no size at all for an icon in running text: it is then 1.25 times the font size and grows with it. A wide icon (a 4:3 flag) keeps its own ratio at every size.

Color and a label v0.16.1

The icon is painted in currentColor, so the text color of the icon (or of its parent) colors it; here the theme colors --oc-success, --oc-warning and --oc-destructive, which change with light and dark. An icon that carries meaning, such as the state of an invoice here, gets a label: it becomes role="img" with that name and a <title> (hover it). Without a label the icon is decorative and hidden from screen readers.

Register the icons you use

The icon data comes from the Iconify JSON packages of the six sets (npm i -D @iconify-json/mdi @iconify-json/flag …), installed in your own project. Nothing is fetched at run time. A whole set is large (MDI is about 3 MB), so a production app registers only the icons it uses.

Best: a small file with only your icons

npx omniaui webicons reads the installed sets and writes one JSON file with just the icons you name, or every icon name it finds in your source with --scan. Run it again when you use a new icon (or in a prebuild script).

npx omniaui webicons --scan src --out src/webicons.json # or by name npx omniaui webicons mdi:home-outline mdi:cog-outline flag:be-4x3 --out src/webicons.json // main.tsx (React) or main.ts (Vue): once, before the app renders import { addWebicons } from "@birdycom/omniaui-react"; // Vue: from "@birdycom/omniaui-vue" import icons from "./webicons.json"; addWebicons(icons);

A whole set, or part of one

registerWebicons(set) takes an Iconify JSON set. Handy while you build; your bundle then holds the whole set. With a list of names only those icons are kept (the import still adds the file to the bundle, so the subset file above stays the lightest).

import { registerWebicons, addWebicons } from "@birdycom/omniaui-react"; import mdi from "@iconify-json/mdi/icons.json"; import flags from "@iconify-json/flag/icons.json"; registerWebicons(mdi); // every MDI icon registerWebicons(flags, ["be-4x3", "lu-4x3"]); // only these two addWebicons({ "mdi:company": "M12 3L2 12h3v8h14v-8h3z" }); // your own: a 24x24 path or an SVG body

Laravel Blade

<x-oc::webicon> reads the sets from node_modules/@iconify-json/<set>/icons.json of the app, once per request. Faster: write a subset file and list it in config/omniacss.php; it is read first. webicons.path points to another folder with the sets.

v0.17.0 The icon props of the Blade components (icon on a breadcrumb item, a combobox option, a dropdown item, a feature card, the language flags, the theme switch …) go through <x-oc::webicon> too, so they are inline SVG without any script. An icon that is not on disk falls back to <iconify-icon> (fallback="iconify"), so pages that still load the Iconify runtime keep working. Run npx omniaui webicons --scan resources --out resources/webicons.json once to put every icon you use on disk.

// npx omniaui webicons --scan resources --out resources/webicons.json 'webicons' => [ 'files' => [resource_path('webicons.json')], 'path' => env('OMNIACSS_WEBICONS_PATH'), // default: base_path('node_modules/@iconify-json') ],

Plain HTML

Copy the SVG from the HTML tab of a demo (or from the catalog) and keep the classes and attributes: class="oc-icon", viewBox, fill="currentColor" and aria-hidden="true" or a role="img" with a title.

Built in

A small set comes with the React, Vue and Blade packages, so OmniaUI's own components never draw an empty space: mdi:check, mdi:check-all, mdi:close, mdi:menu, mdi:magnify, mdi:dots-vertical, mdi:content-copy, mdi:chevron-down, mdi:chevron-up, mdi:chevron-left, mdi:chevron-right, mdi:arrow-up, mdi:arrow-down, mdi:arrow-left, mdi:arrow-right, mdi:trash-can-outline, mdi:walk, mdi:flag-checkered, mdi:map-marker-outline, mdi:target, mdi:text, mdi:web, mdi:monitor, mdi:white-balance-sunny, mdi:weather-night, material-symbols:arrow-outward-rounded, flag:nl-4x3, flag:be-4x3, flag:fr-4x3, flag:de-4x3, flag:gb-4x3, flag:it-4x3, flag:us-4x3. Your own registrations come first. An icon that is not registered draws nothing and gives one warning in the console (React, Vue) or the log (Blade, with APP_DEBUG).

Components that take an icon name (language menu flags, combobox, dropdown items, breadcrumb, cards, theme switch, the route blocks …) draw it the same way. For a name you did not register there, they still write the <iconify-icon> element as before, so an app that loads the Iconify script keeps working.

name, size, label, bare on all three; fallback in React and Vue. Other attributes (a class, an id) go on the <svg>.
