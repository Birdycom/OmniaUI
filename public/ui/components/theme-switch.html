    Theme switch

    A system / light / dark switch built with radio inputs, color-scheme, light-dark() tokens and :has(): the whole page follows without JavaScript. Inside an element with .oc-theme-scope the switch themes only that element, as in the demo below.

    Demo

    snippets/theme-switch.html0 KB JavaScriptBaseline

    Pick a theme: the card next to the switch follows at once, because every token is light-dark(light, dark). The demo is a theme scope, so the rest of this page keeps its own theme. The markup is also available as the snippet packages/ui/snippets/theme-switch.html.

    One button v0.16.0

    For a narrow header there is no room for three choices. Put data-oc-theme-toggle on one button: each click switches between light and dark. Try it: click a button below and the demo box changes; click again to go back. In these docs every demo box is a .oc-theme-scope, so the button themes only that box (data-theme on the scope, nothing stored). In your own app the button is not inside a .oc-theme-scope and the whole page changes, and the choice is remembered. The button shows where a click takes you: a moon while it is light, a sun while it is dark. That works with two icons, one with .oc-theme-img--light and one with .oc-theme-img--dark; only the one for the current theme is shown. The same two classes work on text, as in the second button. The button needs the script below.

    Language and theme together in a header v0.17.0

    The settings of an app header as one small group: the language as a round flag button and the theme as one button, both without a frame until hover, each with its name in a tooltip under it. .oc-header-settings lines them up; it works in a glass header too. React HeaderSettings (with ThemeToggle for the theme alone), Vue OcHeaderSettings and Blade <x-oc::header-settings> build it from a list of languages; the flags come from the language codes. Try it: the theme button below switches only this demo box; in your app it switches the whole page. The React and Vue versions are controlled (value / onChange, v-model): your app decides what a click themes.

    Remembering the choice v0.16.0

    Switching is CSS only, but CSS cannot remember a choice between page loads. theme.js does that: it stores the choice in localStorage, puts it on <html> as data-theme="light|dark" (and the class .dark), checks the matching radio of every switch and keeps other tabs in step. With System the attribute is removed and the page follows the operating system. Your own CSS and scripts then have one place to look: html[data-theme="dark"].

    1
2
3
4
5
    <!-- 1. In <head>, before the stylesheets: no flash of the wrong theme on load -->
<script>(function(){try{var t=localStorage.getItem("oc-theme"),d=document.documentElement;if(t==="light"||t==="dark"){d.setAttribute("data-theme",t);if(t==="dark")d.classList.add("dark")}}catch(e){}})();</script>

<!-- 2. The script: npx omniaui copy-js theme  puts oc-theme.js in public/js -->
<script type="module" src="/js/oc-theme.js"></script>

    In a bundler: import { initTheme } from "@birdycom/omniaui/theme.js" and call initTheme(document, { storageKey: "oc-theme", darkClass: true }). It returns get(), set("dark") and stop(), and fires oc-theme-change on <html> with detail.choice and detail.theme. A button with data-oc-theme-set="light" sets one value. A toggle or set button inside a .oc-theme-scope sets data-theme on that scope only (not on <html>, not in storage) and fires oc-theme-change on the scope.

    The class .dark (Tailwind, shadcn) v0.17.1

    Does your app switch themes with a class on <html>, as Tailwind and shadcn do? class="dark" works the same as data-theme="dark", and class="light" the same as data-theme="light", also when the operating system is set the other way. On any other element the class themes only that part of the page. The class only sets color-scheme. Every theme token is light-dark(light, dark) and picks its value where it is used, so badges, alerts, buttons, fields, cards and tabs all follow without extra CSS. The theme tokens of OmniaCSS (oc-theme.css) do the same, so this also works without the components.

    1
2
3
4
5
    /* Keep this: the class sets the color-scheme, light-dark() follows it */
.dark { color-scheme: dark; }

/* Avoid: resetting it on .dark makes every light-dark() pick the light value (dark text on a dark page) */
.dark { color-scheme: normal; }

    Re-theme with the tokens, not with a second set of colors under .dark: set --oc-primary, --oc-info and the others to a light-dark() pair once, and both themes are covered. --oc-info (with --oc-info-foreground) sits next to --oc-success, --oc-warning and --oc-destructive; the info badge, alert and toast use it.
