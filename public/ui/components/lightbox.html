    Lightbox

    A full-screen image viewer on a native <dialog>: dark blurred backdrop, previous / next, a "2 / 5" counter and a caption. Thumbnails open it with invoker commands, the photos sit in a scroll-snap track and the arrows are plain links, so it works without JavaScript. All components.

    Demo

    Component snippets/lightbox.html Newest CSSv0.6.0

    Click a thumbnail. Use the arrows, swipe, or the arrow keys; Esc or a click on the backdrop closes the viewer. The tiny script only makes each thumbnail open at its own photo.

<script>
document.addEventListener("command", (e) => {
  const id = e.source?.dataset.ocLightboxSlide;
  if (id) requestAnimationFrame(() => document.getElementById(id)?.scrollIntoView({ behavior: "instant", block: "nearest", inline: "center" }));
}, true);
// Optional: prev / next scroll without putting #slide in the address and the history (without this script they
// are plain links), and closing removes a slide hash of this viewer from the address.
document.addEventListener("click", (e) => {
  const nav = e.target.closest?.("dialog.oc-lightbox a.oc-lightbox__nav");
  const slide = nav && document.getElementById(decodeURIComponent(nav.hash.slice(1)));
  if (!slide) return;
  e.preventDefault();
  slide.scrollIntoView({ behavior: matchMedia("(prefers-reduced-motion: reduce)").matches ? "instant" : "smooth", block: "nearest", inline: "center" });
});
document.addEventListener("close", (e) => {
  const slide = e.target.matches?.("dialog.oc-lightbox") && location.hash && document.getElementById(decodeURIComponent(location.hash.slice(1)));
  if (slide && e.target.contains(slide)) history.replaceState(history.state, "", location.pathname + location.search);
}, true);
</script>

    Reference

    Styles live in packages/ui/src/parts/media-lightbox.css. The viewer is always dark; the thumbnails follow the light / dark theme tokens.

    Class / attributeDescription
    .oc-lightbox-thumbs / .oc-lightbox-thumbThumbnail grid and the buttons that open the viewer
    dialog.oc-lightboxFull-screen viewer; --single hides nav and counter
    .oc-lightbox__bar / __title / __closeTop bar with title and close button
    .oc-lightbox__trackSnapping row of slides (give it tabindex="0")
    figure.oc-lightbox__slideOne photo; needs an id for the nav links

    FeatureRole
    <dialog> + ::backdropTop layer, focus trap, dark blurred backdrop
    command / commandforOpen and close without a script
    scroll-snap-typeOne photo per screen
    backdrop-filterBlur behind the viewer

    How it works without JavaScript

    • Open / close: thumbnails are <button command="show-modal" commandfor="…">; the close button uses command="close". closedby="any" closes on Esc and on a backdrop click.
    • One dialog, many slides: the slides sit side by side in .oc-lightbox__track with scroll-snap-type: x mandatory. Swipe, drag and arrow keys move one photo at a time.
    • Prev / next are links to the slide ids. Following a fragment link scrolls the track to that slide. Point the first "previous" at the last slide to loop.
    • Counter is plain text per slide ("2 / 5"), so nothing has to be computed.
    • Optional script (5 lines): listens to the command event and jumps to the slide in data-oc-lightbox-slide. Without it the viewer opens at the first photo.
    • Older browsers without invoker commands: add the small invokers polyfill, or call dialog.showModal() from a click handler.

    Accessibility and keyboard

    • A modal <dialog> traps focus and makes the page behind it inert. Give it an aria-label (or aria-labelledby the title).
    • autofocus on the track puts focus there when the viewer opens, so ←/→ work right away. Tab reaches close, previous and next.
    • Thumbnail buttons need a label ("Open photo 2: …"); photos need alt text (or role="img" + aria-label for placeholder art).
    • The open animation and smooth scrolling only run under prefers-reduced-motion: no-preference.
