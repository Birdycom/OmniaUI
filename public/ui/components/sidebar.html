    Sidebar

    Vertical navigation in two variants. The app sidebar (.oc-sidebar) is a panel with header, icons, badges, collapsible groups and a footer, for dashboards and back offices. The docs sidebar (.oc-sidebar.oc-sidebar--docs) is the navigation you see on the left of this very page: titled groups of outlined links, with the section you are in highlighted. Both share the same parts and the same aria-current="page" active state. All components.

    How it is built

    • Root: a <nav> with .oc-sidebar.oc-sidebar--docs and an aria-label that names the section, so a screen reader announces "OmniaCSS Docs, navigation".
    • Title: .oc-sidebar-title, one per sidebar (an h2 in the page outline).
    • Groups: each group is a .oc-sidebar-group-label (a short uppercase heading) followed by a ul.oc-sidebar-menu. Groups are plain siblings without a wrapper; the label is purely visual.
    • Items: a.oc-sidebar-menu-button inside an li. Every item is a real link, so middle click, copy link and no-JavaScript all work.
    • Active page: aria-current="page" on the link of the page you are on. A parent section that contains the current page gets .is-active (highlighted without announcing it as the current page). Do not put aria-current="page" on two links.
    • Sub items: a nested ul.oc-sidebar-menu-sub directly after the parent link, with a dashed guide line and smaller text.
    • Collapsible groups: for very long lists swap the parent link for <details class="oc-sidebar-collapsible"><summary class="oc-sidebar-menu-button">. No script needed; the open state is native.

    Scrolling behaviour

    The component itself does not scroll. The docs shell gives the left column height: 100%; overflow: auto, so a long menu scrolls inside its own column while the header stays put. After navigating, the docs restore the scroll position of the menu (a few lines of script in the layout; the component does not depend on it).

    App sidebar

    Anatomy, from top to bottom. Markup is also available as the snippet packages/ui/snippets/sidebar.html.

    1. Header (.oc-sidebar-header): logo or workspace switcher. Use .oc-sidebar-menu-button--lg for the taller brand row.
    2. Content (.oc-sidebar-content): the only part that scrolls, so header and footer stay visible.
    3. Group (.oc-sidebar-group + optional .oc-sidebar-group-label): a labelled section. Separate groups with .oc-sidebar-separator.
    4. Menu item (.oc-sidebar-menu-button): a link (or button) with an icon (.oc-sidebar-menu-icon), a label (.oc-sidebar-menu-label, hidden in the icon rail) and optionally a count (.oc-sidebar-menu-badge).
    5. Collapsible group (details.oc-sidebar-collapsible): the summary is the parent item, the chevron comes from CSS, the children live in .oc-sidebar-menu-sub. Add open to start expanded.
    6. Footer (.oc-sidebar-footer): user, plan or help link, for example with the User component.

    Icon-only mode: add .oc-sidebar--collapsed (labels, badges and sub menus are hidden, items are centered). Other modifiers: --right (border on the other side) and --floating (rounded, shadowed card). The width comes from --oc-sidebar-width and --oc-sidebar-width-icon, so you can resize it with one custom property.

    Accessibility, keyboard and responsive behaviour

    • Landmarks: use <nav> (or <aside> with a label) and give each navigation its own aria-label ("Main navigation", "On this page"), so landmark lists are distinguishable.
    • Current page: aria-current="page" is both the accessibility state and the styling hook. Color is not the only cue: the active item is also bolder (app) or outlined (docs).
    • Keyboard: Tab / Shift+Tab move through links, Enter follows a link, Space or Enter on a summary opens or closes a collapsible group. Focus is shown with a 2px ring in --oc-ring.
    • Disabled: aria-disabled="true" dims the item and blocks pointer events; also remove the href so it cannot be reached by keyboard.
    • Themes: all colors are --oc-* tokens (light and dark), nothing to configure.

    Collapse on mobile with CSS only

    Hide the sidebar below a breakpoint and reveal it with a checkbox. The label is a normal button and the checkbox state is read with :has(). Without CSS support the sidebar simply stays visible, which is the safe fallback.
